# Model Deployment: SuperKart Sales Forecasting

A local, end-to-end machine-learning deployment: train an XGBoost regression pipeline,
serve it from a Flask API, and drive it from a Streamlit UI. Predicts a product's total
store sales from product and store attributes.

Everything runs **locally** (the API binds to `127.0.0.1`); there is no cloud dependency.

## What this demonstrates

The point is the deployment discipline, not the sales domain:

- **One self-contained artifact.** The whole model is a single sklearn `Pipeline`
  (preprocessing + XGBoost), saved as one `.pkl`. Serving just calls `pipeline.predict`
  on raw features.
- **No training/serving skew.** Training and the API call the *same* `src/data.py`
  feature prep, so the features are identical in both places. (The original kept a separate
  scaler and hand-rebuilt 30 one-hot columns in the API, the classic way deployments drift.)
- **Local-first.** Flask bound to localhost, Streamlit talking to it, optional Docker
  images for each. No external services.

Test performance (20% holdout): **R² 0.928, RMSE ~287, MAE ~120, MAPE 4.4%**.

## Quickstart

```bash
uv sync

# 1. Train the model (creates models/superkart_pipeline.pkl)
uv run python -m src.train

# 2. Serve it (http://127.0.0.1:7860)
uv run python api/app.py

# 3. In another terminal, launch the UI (http://localhost:8501)
uv run streamlit run frontend/streamlit_app.py
```

Predict from the command line:

```bash
curl -s -X POST http://127.0.0.1:7860/predict -H 'Content-Type: application/json' -d '{
  "Product_Weight": 12.66, "Product_Sugar_Content": "Low Sugar",
  "Product_Allocated_Area": 0.07, "Product_Type": "Dairy", "Product_MRP": 150.0,
  "Store_Id": "OUT004", "Store_Establishment_Year": 1999, "Store_Size": "Medium",
  "Store_Location_City_Type": "Tier 2", "Store_Type": "Supermarket Type2"
}'
# -> {"predicted_sales": 2957.57, "currency": "INR", "status": "success"}
```

## Structure

```
model-deployment/
  data/SuperKart.csv
  src/
    data.py        shared feature prep (used by training AND the API)
    train.py       builds the pipeline, evaluates, saves the artifact
  models/          superkart_pipeline.pkl  (regenerated by src.train; gitignored)
  api/
    app.py         Flask service, loads the pipeline, POST /predict
    Dockerfile
  frontend/
    streamlit_app.py   local UI, talks to the API (SUPERKART_API env var to override)
    Dockerfile
  notebooks/
    01-train-and-evaluate.ipynb   training story, metrics, plots
  results/         figures written by the notebook
```

## Docker (optional)

```bash
docker build -f api/Dockerfile -t superkart-api .
docker run -p 7860:7860 superkart-api
docker build -f frontend/Dockerfile -t superkart-ui .
docker run -p 8501:8501 -e SUPERKART_API=http://host.docker.internal:7860 superkart-ui
```
